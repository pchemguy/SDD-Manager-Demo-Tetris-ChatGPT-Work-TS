# Milestone 1.4 — Desktop presentation and delivery

Reviewed T-017–T-020 through 4b65a9d, 2026-10-09. The desktop baseline now has responsive square-cell/DPI-aware Canvas, readable HTML statistics/next/status, complete instructions, keyboard Restart and reproducible static delivery.

## Code review

Inspected renderer/view/styles/semantic shell, composition/controller integration, strict tooling/lockfile, production/browser harnesses, setup/API documentation and secret/generated-output exclusions. Canvas backing dimensions track measured CSS/DPI, with a fixed 1:2 board ratio even when axes would round differently. View only writes changed text, avoiding repeated live-status announcements. Browser scenarios test the built static app; engine state is not injected through a production hook. Source/module/API documentation and local links match the implementation. No required defect remains.

Resolved findings:

- M1.4-01 — Independent backing-axis rounding (renderer.prepare) produced a one-pixel mismatch in Firefox at fractional CSS sizes. T-019 added a behavioral RED regression, derives board height from width and scales to actual backing dimensions; unit/pixel/resize checks pass.
- M1.4-02 — Firefox fixture replacement after engine creation did not replace its captured source; Classic WebDriver's global realm also differed from the page. T-020 uses BiDi preload before startup and changes the page-window fixture callback. The forced-I rotation assertion exposed the realm issue; verified O fixtures and I rotation/lock/spawn now pass reproducibly.
- A browser hold assertion previously depended on wall-time scheduling under parallel load. T-019 uses Playwright's controlled clock for that layer; stable Firefox separately verifies native wall-time holds and actual tab visibility.

## Environment and evidence limits

All browser acceptance uses headless Linux automation. Full Chrome cannot create its ProcessSingleton Unix socket in this sandbox; the official Stable headless shell supplies the current Chromium desktop engine. Chrome browser UI/graphical OS focus integration is not claimed. Native Firefox tab switching establishes real blur/visibility events. Process-scoped Firefox sandbox flags/font configuration recover the standard sandbox's restrictions; browser assets are external to npm ci. No global Python environment changed.

The usable desktop UI includes Space/hold/focus instructions and explicit paused/game-over labels. Non-baseline modern features remain outside the accepted campaign.
