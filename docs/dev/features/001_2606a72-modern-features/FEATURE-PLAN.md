## Strategy and earliest useful increment

Start with ghost and hard drop in the real built browser game, including the Space/P mapping and full grounded lock interval. This gives a useful changed path immediately while retaining the baseline's independent selection for this increment only. Then add bag/hold together with their fixture and browser adaptations, add horizontal kicks and complete interaction checks, and finish desktop/static delivery. No setup-only milestone or new dependency is required before visible usefulness.

Fixture adaptation accompanies each changed contract. In particular, bag selection must not leave tests expecting unlimited repeated-O draws or make regressions falsely pass on uncontrolled pieces. Keep deterministic construction in test helpers/public commands and preload browser randomness before startup. There is no production state loader, alternate selection mode, or infrastructure detour.
